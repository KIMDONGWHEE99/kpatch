# 작업 사본 정리

대상: $ARGUMENTS

삭제는 되돌릴 수 없다. 조사와 목록 작성까지는 읽기 전용으로 하고, 사용자가 목록을 승인한 뒤에만 지운다.

## 1. 조사 (읽기 전용)

1. 프로젝트 드라이브의 여유 공간을 기록한다.
2. `working_private`, `build_candidate`, `source_original`, `extracted_private`, `release_output`의 게임별 하위 폴더 크기를 잰다. 파일이 많은 폴더는 오래 걸리므로 하위 폴더 단위로 나눠 잰다.
3. 큰 폴더는 안을 열어 무엇인지 확인한다. 이름만 보고 판단하지 않는다.

## 2. 분류

| 분류 | 대상 | 처리 |
|---|---|---|
| 삭제 권장 | 설치 시험용 게임 사본(`tests*`), 복원 검증 파일(`*.rebuilt`), 검수용 게임 사본, 최신 통과본이 아닌 후보, ZIP과 내용이 같은 풀린 폴더(최신판 제외) | 목록에 올린다 |
| 사용자 판단 | 원본 게임 전체 사본, 구버전 ZIP, 검수 때의 재추출 자료, 대용량 상태 기록 | 지웠을 때의 제약을 적어 따로 묻는다 |
| 보존 | 번역 원본, 도구, 보고서, 로그, 캡처, 해시·build 기록, 최종 ZIP, 최신 후보, 설치 백업(`installation_backup`), 분석 도구가 쓰는 실행 환경 | 건드리지 않는다 |

분류와 보관 기준은 `docs/KOREAN_PATCH_PLAYBOOK.md` 11절이다. 번역 폴더가 있는 `working_private/<게임>` 폴더는 통째로 지우지 않는다.

원본 게임 사본을 지우면 게임이 업데이트된 뒤에는 그 빌드를 다시 구할 수 없다. 설치 백업은 설치본을 원본으로 되돌리는 수단이므로 지우지 않는다.

## 3. 삭제 전 확인

1. 도구 의존성: 삭제 후보 경로를 `tasks/<게임>`과 `tools`의 코드와 문서에서 검색한다. 도구나 안내 문서가 입력으로 직접 읽는 폴더는 남기거나 사용자 판단으로 옮긴다.
2. 링크: 삭제 대상 안에 심볼릭 링크나 정션이 있는지 확인한다. 있으면 그 항목은 제외하고 보고한다.
3. 무결성: 남길 최신 후보와 최종 ZIP의 SHA-256이 기록과 일치하는지 확인한다. 일치하지 않으면 삭제를 멈춘다.
4. ZIP 쌍: 풀린 폴더를 지우기 전에 같은 이름의 ZIP과 파일 목록·크기가 같은지 확인한다.

## 4. 승인 요청

삭제 권장, 사용자 판단, 보존을 나눠 경로와 용량, 지웠을 때의 영향을 보고한다. 사용자가 범위를 정할 때까지 지우지 않는다.

## 5. 삭제와 검증

1. 승인된 경로만 하나씩 명시해 지운다. 와일드카드로 상위 폴더를 지우지 않는다. PowerShell에서는 `Remove-Item -LiteralPath "<경로>" -Recurse -Force`를 쓴다.
2. 지운 뒤 보존 대상이 그대로 있는지 확인한다.
3. 여유 공간을 다시 재서 전후 차이를 보고한다.

## 6. 기록

`WORK_LOG.md` 끝에 날짜, 지운 경로, 확보 용량, 보존한 것, 재실행 시 영향을 한 단락으로 남긴다. 2026-11-16 기록이 예시다. 게임 실행이나 재검증을 하지 않았다면 그렇게 적는다.
