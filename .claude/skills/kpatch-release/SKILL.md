# 패키징·설치 시험·배포 (G6~G8)

대상: $ARGUMENTS

통과 기준은 `docs/KOREAN_PATCH_PLAYBOOK.md` 8절, 사본 보관 기준은 같은 문서 11절이다. 이 스킬은 순서와 디스크 사용 규칙을 정한다.

## 시작 전

1. G4와 G5의 유효한 증거가 같은 후보 해시에 연결돼 있는지 확인한다. 아니면 중단하고 이유를 보고한다.
2. 여유 공간을 확인한다. 여유가 (게임 크기 × 3) + 20GB보다 적으면 `/kpatch-cleanup`을 먼저 한다.
3. 설치기와 시험 도구는 기존 것을 복사해 쓴다. 최신형은 `tasks/THE_HORDE_OF_GORAK`, `tasks/COBALT_MINER`, `tasks/HOW_EMPIRES_WORK/tools`에 있다.

## 순서

1. 후보 고정: 전체 파일 목록과 해시를 기록한다.
2. 차이 패치: 만든 직후 정방향(원본→후보)과 역방향(후보→원본)으로 복원해 해시를 확인한다. 복원으로 만든 파일은 해시를 기록한 직후 지운다.
3. 허용 목록: 설치·제거기, 차이 패치 도구와 라이선스, 문서, 차이 파일만 넣는다.
4. 최종 ZIP: 만든 뒤 해시를 고정한다. 이후 설치 시험은 이 ZIP에서 꺼낸 파일로만 한다.
5. 설치 시험: 지침서 8절의 시험군 표를 적용한다. 아래 디스크 규칙을 지킨다.
6. 보고: ZIP 밖의 결과 보고서가 ZIP 해시와 시험 결과를 참조하게 한다.
7. 실제 설치와 공개는 사용자가 허용한 범위에서만 한다.

## 설치 시험의 디스크 규칙

2026-11-10 How Empires Work 설치 시험은 사례 30여 개마다 게임 전체를 복사해 남겨 두었고, 39GB를 쓴 끝에 디스크 부족으로 실패했다. 같은 일을 막기 위해 다음을 지킨다.

- 사례 하나가 끝나면 시험 도구가 그 사례의 게임 사본을 바로 지운다. 결과는 사례 ID, 판정, 관련 해시, 오류 메시지를 JSON 한 건으로 남긴다.
- 실패한 사례의 폴더만 원인 분석이 끝날 때까지 남긴다.
- 사본에는 설치기가 확인하는 파일(매니페스트의 변경 파일과 빌드 식별 파일)만 넣는다. 설치기가 전체 폴더를 요구하는 사례만 게임 전체를 복사한다.
- 시험 도구에 `copytree`만 있고 삭제가 없으면 실행하기 전에 사례별 삭제를 넣는다. 삭제 처리의 예는 `tasks/COBALT_MINER/test_installer.py`에 있다.
- 쓰기 실패 시험은 작은 격리 자료나 실패 주입으로 한다. 실제 디스크를 채우지 않는다.
