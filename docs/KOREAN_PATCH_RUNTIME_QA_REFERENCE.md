# 한글패치 런타임 글꼴·실행 QA 참조문서

작성일: 2026-08-29  
사례: SuperReap Demo 한국어 패치 1.0.0 → 1.0.1

현재 역할: [핵심 지침서](KOREAN_PATCH_PLAYBOOK.md)의 G3(글꼴)·G5(그래픽·저장 격리)를 위한 상세 참조입니다. 아래 사고·수치는 당시 기록입니다. 신규 배포의 상태·증거 만료·최종 ZIP 판정은 핵심 지침서 G0~G8을 함께 적용합니다.

2026-09-05 보완: 프로세스 경로·번호는 실행 때 실제 수집하고, 캡처·로그·검수 사본의 허용 변경을 후보 해시에 연결합니다. 저장 격리는 제품명뿐 아니라 실제 쓰기 위치·설정·로그·외부 전송까지 확인합니다. 첫 화면 통과나 과거 보고서만으로 대표 흐름 검증을 통과시키지 않습니다.

## 1. 문서 목적

이 문서는 한글패치가 정적 검증을 모두 통과했는데도 실제 게임에서 한글이 `□`로 표시된 사례를 재발 방지 기준으로 정리한 문서입니다.

새 한글화 작업에서는 문자열 추출·번역뿐 아니라 글꼴의 실제 렌더링 가능성과 그래픽 실행 결과까지 이 문서의 게이트를 적용합니다. 여기서 말하는 “원큐 성공”은 내부 시행착오가 전혀 없다는 뜻이 아니라, 결함을 사용자에게 전달하기 전에 제작·검증 단계에서 발견한다는 뜻입니다.

| 항목 | 내용 |

| 탐지 실패 원인 | 그래픽 없는 배치 실행은 실제 한글 글리프 생성·렌더링을 충분히 유발하지 않음 |

| 최종 확인 | 그래픽 첫 화면 정상 표시, 한글 글리프 누락 경고 0건, 설치기 시험 12종 통과 |

## 3. 핵심 교훈

### 3.1 Font의 한글 지원과 TMP의 한글 출력은 다르다

원본 TTF/OTF Font의 `cmap`에 한글 코드포인트가 존재하는 것만으로 화면 출력을 보장할 수 없습니다. TMP는 별도의 FontAsset, 문자표, 글리프표, 아틀라스 텍스처와 동적 생성 정책을 사용합니다.

다음 조건을 구분해 검사해야 합니다.

1. 원본 Font 데이터에 필요한 글자가 있는가?
2. TMP `m_CharacterTable`에 필요한 글자가 이미 있는가?
3. 없다면 `m_AtlasPopulationMode`가 동적 모드인가?
4. `m_SourceFontFile`이 실제 한글 Font를 가리키는가?
5. 기존 아틀라스에 공간이 있는가?
6. 공간이 부족할 때 `m_IsMultiAtlasTexturesEnabled`가 활성화되어 있는가?
7. 폴백 글꼴과 실제 텍스트 객체의 글꼴·재질 연결이 유효한가?

안전한 판정은 다음과 같습니다.

```text
정적 TMP 글꼴:
  필요한 모든 문자가 m_CharacterTable과 m_GlyphTable에 있어야 통과

동적 TMP 글꼴:
  원본 Font에 필요한 문자가 있고
  m_SourceFontFile이 유효하며
  동적 생성 모드이고
  다중 아틀라스가 활성화되어야 통과
```

아틀라스의 빈 사각형 목록만 보고 모든 글자가 들어간다고 추정하지 않습니다. 글자마다 크기와 패킹 결과가 다르므로, 충분한 여유를 계산할 수 없다면 다중 아틀라스를 활성화하고 실행 검증으로 확인합니다.

### 3.2 참조가 맞는지와 참조 대상이 작동하는지는 별도 검사다

SuperReap 사례에서는 TMP 텍스트 941건이 의도한 Fusion FontAsset을 정확히 가리켰습니다. 하지만 참조 대상 FontAsset 자체가 한글을 추가할 수 없는 상태였습니다.

따라서 다음 두 검사를 분리합니다.

- 참조 무결성: 모든 실제 텍스트 객체가 의도한 글꼴을 참조하는가?
- 대상 기능성: 그 글꼴이 필요한 글자를 실제로 생성하고 렌더링할 수 있는가?

빌드 도구와 검증 도구가 같은 `expected_font` 함수만 사용하는 자기검증으로 끝내지 않습니다. 독립적인 글리프·아틀라스 검사와 그래픽 실행 결과가 필요합니다.

### 3.3 글자가 들어 있는 파일만 조사하면 글꼴 전용 묶음을 놓칠 수 있다

실제 FontAsset이나 Source Font가 텍스트 객체와 다른 AssetBundle에 존재할 수 있습니다. 텍스트 사용 목록만으로 수정 대상 파일을 만들면 글꼴만 보관된 묶음이 빠질 수 있습니다.

다음 의존 관계를 끝까지 추적합니다.

```text
텍스트 객체
  → TMP FontAsset
    → Source Font
    → Atlas Texture
    → Material
    → Fallback FontAsset
```

각 대상이 내부 객체인지 외부 파일 참조인지 확인하고, 참조된 모든 자산 파일을 패치·카탈로그·배포 대상에 포함합니다.

### 3.4 런타임 조합 문구는 실제 소비 UI까지 연결해 검사한다

장면에 저장된 원문을 번역하는 것만으로 충분하지 않습니다. 다음처럼 실행 중 만들어지는 문구가 있습니다.

- `데모 버전` + 버전 번호
- 숫자 + 단위
- enum의 `ToString()` 결과
- 이름 + 조사 또는 접미사
- 자리표시자를 치환한 대화·알림

각 조합 문구에 대해 다음을 기록합니다.

- 생성 메서드와 서식 문자열
- 최종 문자열 예시
- 화면에 표시하는 TMP/Text 객체
- 그 객체가 실제 사용하는 글꼴·재질·폴백

문자열이 번역됐다는 사실과 최종 소비 UI가 그 글자를 출력할 수 있다는 사실을 함께 검증합니다.

## 4. 필수 배포 게이트

### 4.1 문자열 게이트

- `VISIBLE_TRANSLATE`, `VISIBLE_KEEP`, `INTERNAL`, `MEDIA`, `UNKNOWN` 분류 완료
- `UNKNOWN` 0건
- 번역 대상 누락 0건
- 번역 위치의 원문 잔존 0건
- 태그·토큰·아이콘 태그·자리표시자 차이 0건
- 런타임 조합 문구와 화면 표시 enum 포함

### 4.2 글꼴 게이트

- 전체 번역 말뭉치에서 필요한 문자 집합 계산
- 실제 사용 Font와 TMP FontAsset을 파일별·경로 ID별로 목록화
- 정적 TMP 글꼴은 필요한 문자가 문자표·글리프표에 모두 존재
- 동적 TMP 글꼴은 원본 Font의 글리프, Source Font 참조, 동적 모드 확인
- 동적 TMP 글꼴은 다중 아틀라스 활성화 확인
- 폴백 체인 순환·누락 0건
- 텍스트 객체의 글꼴과 재질 호환성 확인
- 기본 자산과 AssetBundle에 중복된 글꼴 자산을 모두 확인

### 4.3 카탈로그·패키지 게이트

- 수정된 모든 AssetBundle이 Addressables/YooAsset 목록에 반영됨
- 번들 크기·CRC·해시 정책을 원본 로딩 방식에 맞게 갱신
- 목록 파일을 다시 파싱할 수 있음
- 원본·후보 파일 크기와 SHA-256 기록
- VCDIFF 생성 직후 정방향·역방향 적용 해시 일치
- 원본, 이전 패치, 중복 설치, 부분 설치, 변조, 제거 시험 통과

### 4.4 그래픽 실행 게이트

최소한 다음 화면을 실제 그래픽 장치로 실행해 확인합니다.

1. 제작사 로고와 첫 화면
2. 메인 메뉴와 설정
3. 새 게임 또는 이어하기 진입
4. HUD, 알림, 숫자·단위 조합 문구
5. 대화와 선택지
6. 일시정지·도움말·접근성 화면
7. 사망·결과·데모 종료 화면

각 구간에서 다음을 수행합니다.

- 대표 화면 캡처
- `□`, 깨진 자모, 잘림, 겹침, 태그 노출 육안 확인
- Player.log의 `The character with Unicode value` 경고 0건 확인
- 패치 전 원본과 비교해 패치 고유 로딩·카탈로그 오류 0건 확인

배치 모드는 자산 재열기와 비그래픽 초기화 확인에만 사용합니다. 배치 모드 통과를 화면 출력 QA로 간주하지 않습니다.

## 5. 안전한 실행 QA 절차

### 5.1 후보 복사본 실행 여부 확인

Steam 게임은 후보 폴더의 실행 파일을 실행해도 Steam이 설치 경로의 게임을 다시 띄울 수 있습니다. 다음을 모두 확인합니다.

- 테스트용 `steam_appid.txt`가 필요한 게임인지 확인
- 실행 뒤 프로세스의 실제 `Path`가 후보 복사본인지 확인
- 기대하지 않은 설치 경로 프로세스가 실행되면 즉시 중단
- 테스트가 끝나면 임시 Steam 식별 파일 제거

### 5.2 사용자 저장 데이터 격리

- 가능하면 후보의 제품명을 같은 길이의 테스트 전용 이름으로 임시 변경
- 테스트 전용 `persistentDataPath`가 만들어졌는지 확인
- 기존 사용자 저장 파일의 크기·해시와 핵심 값을 실행 전 기록
- 실행 후 원본 사용자 저장 데이터가 바뀌지 않았는지 확인
- 임시 제품명, footprint, 테스트 저장 폴더를 원상 복구 또는 격리 보관

사용자에게 반복 플레이를 요청하는 것은 보조 검수입니다. 최초 실행·핵심 화면·글꼴 로그 확인은 제작자가 배포 전에 수행합니다.

## 6. 재발 방지 체크리스트

아래 항목 중 하나라도 `아니요`이면 릴리스하지 않습니다.

- [ ] 실제 사용 TMP FontAsset을 모두 찾았는가?
- [ ] FontAsset이 있는 글꼴 전용 묶음까지 찾았는가?
- [ ] 필요한 문자 집합을 전체 번역 말뭉치에서 계산했는가?
- [ ] 정적 문자표 또는 동적 생성 조건을 독립적으로 검증했는가?
- [ ] 동적 글꼴의 다중 아틀라스가 활성화됐는가?
- [ ] 런타임 조합 문구와 실제 소비 UI를 연결했는가?
- [ ] 첫 화면을 포함한 대표 화면을 그래픽 모드로 직접 확인했는가?
- [ ] Player.log의 한글 글리프 누락 경고가 0건인가?
- [ ] 실행 프로세스 경로가 후보 복사본임을 확인했는가?
- [ ] 사용자 저장 데이터가 격리 또는 원상 복구됐는가?
- [ ] 이전 패치에서 최신 패치로 갱신되는 설치 시험을 했는가?
- [ ] 실제 설치 대상 파일의 최종 SHA-256을 확인했는가?

## 7. 완료 표현 기준

- 정적 검사만 했으면 `정적 검증 완료`라고 기록합니다.
- 첫 화면만 확인했으면 `첫 화면 그래픽 QA 완료`라고 범위를 명시합니다.
- 대표 흐름을 확인했으면 확인한 화면과 저장 데이터 조건을 나열합니다.
- 전체 회차와 모든 분기를 확인하지 않았다면 `완벽 한글화`, `전체 실행 QA 완료`라고 단정하지 않습니다.
