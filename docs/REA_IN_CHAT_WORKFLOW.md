Claude Code에는 REA가 아직 연결돼 있지 않으며, 연결 절차는 [Claude Code 설정 안내 4절](CLAUDE_CODE_SETUP.md)을 따릅니다. 아래의 "현재 확인한 상태"와 "현재 환경에 적용한 설정"은 2026-10-31 Codex 환경의 기록입니다. 그때 `JAVA_HOME`으로 지정한 `working_private/SOULASH_2/toolchain/jdk-21.0.12.1+1` 폴더는 2026-11-16에 확인했을 때 없었습니다. 질문을 좁혀 필요한 함수만 조사하고 실제 응답으로 확인한다는 사용 원칙은 Claude Code에서도 그대로 적용합니다.

## 제작자가 수행하는 순서

1. 프로젝트 지침·게임 명세와 기존 번역 파일을 읽고 엔진·빌드·원본 지문을 확인합니다. JSON·CSV·Unity 자산·복원 가능한 코드로 해결되는 작업부터 진행합니다.
2. REA가 필요한 질문을 하나로 좁힙니다. 예: “화면의 `None`은 어디서 출력되는가”, “이 이름이 저장 형식에도 쓰이는가”. 답을 얻으면 어떤 수정과 검증을 할지 함께 적습니다.
3. 현재 연결 도구에서 해당 기능과 입력 형식을 확인합니다. 연결·엔진 준비 여부가 불명확하거나 오류가 있을 때만 `binary_session`으로 상태를 확인합니다. 매 질문마다 전체 진단을 반복하지 않습니다. 응답은 상태·해당 제공자·오류만 요약합니다.
4. 네이티브 실행 파일·DLL의 코드 분석에는 **Ghidra를 기본 분석기로 사용**합니다. 보호된 원본 사본의 절대 경로와 `provider_id: "ghidra"`를 지정해 `open_binary`를 호출합니다. 필요한 문자열·참조로 함수를 좁히고 `analyze_function` 또는 `procedure_pseudo_code`의 실제 함수 응답을 확인합니다. 연결 상태의 `available`만으로 분석 성공을 판정하지 않습니다. 같은 입력의 유효한 Ghidra 결과가 있으면 재사용합니다. Ghidra가 작동하지 않으면 원인과 복구·대체 경로를 기록하며, 다른 도구의 결과를 Ghidra 분석으로 표시하지 않습니다. 관리 코드나 다른 형식에는 해당 형식 전용 도구를 우선합니다. 도구의 실제 입력 형식을 따르며 전체 함수 복원을 기본으로 하지 않습니다.
5. 결과를 번역·수정 도구에 연결하고 독립 재추출·변경 경계·실제 화면 및 저장 검증을 수행합니다. REA 분석 성공은 게임 실행 검증을 대신하지 않습니다.
6. 같은 대상·설정의 열린 세션과 유효한 보존 응답을 재사용합니다. 마칠 때 필요한 증거와 지원되는 스냅샷을 비공개 작업 폴더에 보존하고 `close_binary`로 정리합니다. 스냅샷 재사용에도 제공자 시작이 필요할 수 있으며 모든 분석을 생략한다고 보장하지 않습니다.

위 도구 이름은 **제작자가 대화 안에서 호출하는 기능**입니다. 사용자가 PowerShell에 붙여 넣는 명령이 아닙니다. 일반 파일 수정·패키징에 필요한 내부 명령 실행은 사용할 수 있으나, REA를 쓰기 위해 별도 CLI 실행기를 만드는 것을 기본 절차로 삼지 않습니다.

이는 현재 PC의 설치 경로이며 다른 컴퓨터에 그대로 적용하는 값이 아닙니다. 향후 도구 폴더를 옮기거나 삭제하면 함께 갱신해야 합니다. 새 게임마다 Ghidra를 재설치하거나 게임별로 복사하지 않습니다. 기존 한글 설치 경로의 로깅 오류와 임시 경로 문제를 고려해 Ghidra 및 분석 임시 폴더를 영문 경로로 지정했습니다. TEMP/TMP는 REA 서버에만 적용되며 Windows 전체 환경을 변경하지 않았습니다.

백업은 `C:/Users/PC/.codex/config.toml.before-rea-ghidra-20261031.bak`에 있습니다. 앱의 **설정 → 플러그인 → MCP → 다시 시작**으로 재연결했고, 현재 대화의 `binary_session`과 실제 `analyze_function` 응답을 확인했습니다. 새 설정 파일 저장만으로 실행 중 서버가 바뀐다고 판단하지 않습니다. 앞으로 경로를 바꾸면 같은 순서로 확인합니다. 사용자가 PowerShell 명령을 입력할 필요는 없습니다. [OpenAI 공식 MCP 설정 안내](https://learn.chatgpt.com/docs/extend/mcp), [REA Windows Ghidra 설정](https://github.com/morluto/rea/blob/main/docs/windows-ghidra-p0.md)

현재 호출 제한은 450초입니다. 과거 실행기의 30분 분석 제한을 무조건 복사하지 않습니다. 실제 시간 초과가 발생했을 때 클라이언트 제한과 제공자 제한을 구분하고 반환된 복구 안내에 따라 필요한 값만 바꿉니다. 진행 중 작업의 상태를 확인하지 않은 채 같은 분석을 다시 시작하지 않습니다.

## 비용과 재평가

- 질문별 20분 또는 연속 2회 유효한 근거 미확보 시 제작자가 질문·범위·도구를 재평가합니다. 자동 포기·강제 취소·승인 요청 기준이 아닙니다.
- 전체 도구 목록·`binary_session` 원문·대형 분석 결과를 대화에 반복 출력하지 않습니다. 원시 증거는 비공개 영역에 두고 필요한 필드·차이·예외를 읽습니다.
- 연결된 도구가 충분하면 별도 PowerShell/Python REA 서버를 동시에 만들지 않습니다. 실제로 필요한 기능이 없거나 연결 복구가 불가능한 경우에만 이유를 기록하고 허용된 대체 경로를 선택합니다.
- 필수 검사나 미분류 기준을 줄여 비용을 맞추지 않습니다. 최종 본편·저장/불러오기·수정본·설치 복구 확인을 작업 계획에 먼저 확보합니다.

공식 문서는 데스크톱의 MCP 등록·환경변수·재시작 경로를, 현재 연결 도구의 입력 형식과 응답은 이 대화에서 가능한 동작을 뒷받침합니다. 일반 웹 대화가 로컬 설정을 자동으로 읽는다고 확대 해석하지 않습니다. [OpenAI 공식 안내](https://developers.openai.com/codex/mcp/), [REA 스냅샷 동작](https://github.com/morluto/rea/blob/main/docs/cli.md)
