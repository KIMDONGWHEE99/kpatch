## 다음 신규 게임 시험: 문구별 자동 재적용 (PROC-09)

2026-11-10 진행 기록: How Empires Work의 `reapply_translation.py`에서 원문·위치·문맥·서식 일치 시 재사용 후보를 만들고 변경·신규·모호한 항목을 UNKNOWN/영문으로 남기는 코드와 모의 시험12개를 구현했다. 실제 번역5300행도 검사했다. 자료 수준의 제안·원자적 쓰기 시험이며 미래 빌드 감지, 게임 파일 자동 재적용, 부분 영문 후보의 실제 실행은 미구현/미검증이다. 따라서 PROC-09 전체 상태는 OPEN이다. [이번 범위와 한계](../validation/HOW_EMPIRES_WORK/ko_1.0.0/RESULT_REPORT.md).

2026-11-04 사용자 요청: “그럼 다음 게임 패치때 이 방식으로 한번 테스트해보죠”. 목적은 업데이트 후에도 확인 가능한 기존 번역을 유지하고, 새로 생기거나 변경된 부분은 영어로 남겨 게임을 계속 사용할 수 있게 하는 것입니다. 다음 신규 게임의 TASK_SPEC에 시험 항목을 포함합니다. 현재 Gorak1.0.1에 구현된 기능으로 표시하거나 기존 배포본을 이 방식으로 바꾸지는 않습니다.

- 번역 자료를 Steam이 교체하는 게임 파일과 분리합니다. 대상 엔진의 공식 번역·모드 기능이 있으면 우선 검토하고, 구조에 맞는 실행 전 재적용 또는 표시 시 치환 방식을 소규모로 시험합니다. 게임을 실행하는 경로와 Steam 업데이트 뒤 자동 동작 조건도 확인합니다.
- 파일 전체 해시가 달라졌다는 이유만으로 모든 번역을 포기하지 않습니다. 지원하는 자료 형식을 새로 읽고 원문·안정적인 식별자·객체 문맥·서식이 맞는 항목에 한해 기존 번역을 재사용합니다. 원문만 같은 다른 문맥이나 중복 위치에는 임의로 적용하지 않습니다.
- 신규·수정·모호한 문구는 영어로 유지합니다. 적용·영문 유지·판독 실패의 수와 이유를 별도로 기록합니다. 영문 유지가 허용됐다는 이유로 UNKNOWN을 INTERNAL이나 번역 완료로 바꾸지 않습니다. 읽지 못한 부분이나 안전하게 다시 저장할 수 없는 묶음은 원본을 유지합니다.
- 한글 글꼴·자리표시자·참조 관계를 함께 확인합니다. 지원하지 않는 엔진 구조나 글꼴 변경까지 자동 호환된다고 가정하지 않습니다. 재적용 실패 시 반쯤 수정한 상태를 남기지 않고 복구하며 원본으로 실행할 수 있는 경로를 보존합니다.
- 소규모 원문·한국어·글꼴 시험 뒤, 문구 추가·수정·삭제·위치 이동·중복 문맥·서식 변경·자료 형식 변경을 각각 시험합니다. 중복 적용·설치 중단·업데이트 후 제거·사용자 저장 보존도 검사합니다. 실제 업데이트를 확보하지 못하면 모의 업데이트 시험이라고 명시합니다.
- 성공 판정은 자동 재적용 동작과 적용된 문구의 정확성에 대한 것입니다. 부분 영문 유지와 전체 번역 완료를 구별하고, 기존 G0~G8의 적용·복구·변경 경계 검증을 우회하지 않습니다. 시험 결과와 한계를 확인한 뒤 해당 게임에 사용할 범위를 결정합니다.

PROC-07의 기존 표본은 `tasks/PIBCREMENTAL_DEMO/tools/CatalogPatcher/bin/Release/net8.0/UnityEngine.CoreModule.dll`과 `validation/TFC2/noop_roundtrip/sharedassets0.assets`입니다. 이번에는 이동·삭제·Git 제외 규칙 변경을 하지 않았습니다. 실제 참조 관계 확인 후 이전합니다.

## 미구현 기간의 운영

- 해당 도구의 통과 값만으로 새 완성판을 승인하지 않습니다. 현재 빌드에 대해 독립적으로 같은 조건을 확인한 명령·결과·해시가 있으면 그 증거를 사용합니다.

- 기존 배포본의 손상이나 특정 미번역이 모두 확인된 것은 아닙니다. 과거 결과의 범위를 유지하고, 재검증 없이 새 기준 충족을 선언하지 않습니다.
