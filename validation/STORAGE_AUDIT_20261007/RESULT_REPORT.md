# 저장 공간 조사·중복 파일 정리 결과

조사·정리일: 2026-10-07 · 상태: 확인한 중복 파일 정리 완료

## 확인 결과

사용자는 `source_original`, `extracted_private`, `validation`의 자료를 이미 삭제했다고 알렸다. 현재 세 폴더에는 각각 자리표시자 `.gitkeep`만 남아 있고 `build_candidate`는 존재하지 않는다. `PROJECT_STATUS.md`가 연결하는 기존 결과·검증 파일 16개도 현재 없다.

이는 번역 작업 전체의 손실을 뜻하지는 않는다. 게임별 번역 원본·도구와 많은 원시 검수 자료가 `tasks`와 `working_private`에 남아 있다. 다만 원본 기준선·추출 결과·완성 후보·최종 결과보고서 일부가 없어, 동일한 빌드의 재제작과 과거 검증 재확인에는 복구 또는 재검증이 필요하다. 근거 파일이 사라진 과거 상태를 현재 유효한 통과 결과로 재사용하지 않는다.

`release_output`의 ZIP 19개, 합계 97,979,058바이트에 대해 내부 파일의 CRC(손상 여부 검사)와 현재 SHA-256(내용 지문)을 확인했다. 19개 모두 손상 검사 PASS다. 이 검사는 실제 게임 설치·제거와 실행 검증을 대신하지 않는다. SuperReap의 완성 ZIP과 Vanilla Plus의 개인용 통합 ZIP은 현재 배포 폴더에서 확인하지 못했으며, 관련 남은 제작 자료는 보존한다.

## 중복 파일 정리 계획

`working_private`의 최초 일반 경로 조사는 약 59.15GiB를 집계했다. 일부 긴 경로의 그래픽 임시 파일에서 읽기 오류가 있어 이 전체 크기는 근삿값이다. 삭제 후보 조사는 긴 경로를 지원하는 별도 검사로 수행했고 읽기 오류는 0건이다.

조사한 게임 실행·설치 시험 사본에서 1MiB 이상의 게임 바이너리(실행 파일과 게임 자산)를 선별했다. 같은 게임 안에서 크기와 SHA-256이 모두 같은 파일만 중복으로 판정했고, 삭제 후보마다 남기는 동일 파일의 경로를 연결했다. 모든 보존 파일은 삭제 목록 밖에 있다.

사용자가 ‘확인된 중복 게임 파일만 삭제’를 선택한 뒤 **1,825개, 40,689,262,499바이트(37.895GiB, 약 38GB)**를 삭제했다. 게임별 합계와 개별 파일·보존 사본·내용 지문은 비공개 정리 목록에 기록했다.

실제 디스크 여유 공간은 40,684,019,712바이트(약 37.89GiB) 증가했다. `working_private`의 남은 파일은 조사 기록 폴더를 제외하고 약 21.27GiB다. 다른 프로그램의 임시 쓰기와 조사 기록 생성 때문에 삭제한 파일 크기의 합과 실제 여유 공간 증가에는 작은 차이가 있다.

삭제 전 모든 대상과 보존 사본의 내용 지문을 다시 확인했다. 삭제 후 남긴 게임 사본 216개의 지문을 재검사했고, 비대상 37,544개 파일의 존재·크기·수정 시각에 변화가 없었다. 삭제 대상 잔존·비대상 누락·변경은 각각 0건이며 ZIP 19개의 지문도 그대로였다.

번역 원본, 수정한 코드·장면, 글꼴, 미디어, 스크린샷, 검수·설치 기록, 저장·설정, 도구 소스와 복구용 대표 게임 사본은 삭제 대상에서 제외했다. 설치본의 별도 백업 폴더는 정리 범위에 포함하지 않았다. 폴더 전체를 삭제하지 않는다.

삭제할 파일의 예전 경로를 직접 참조하는 검수 사본은 다시 실행하기 전에 재구성이 필요하다. 삭제 목록의 보존 경로와 내용 지문으로 동일 파일을 되돌려 놓을 수 있지만, 그 행위가 과거 검증을 자동 복원한다는 뜻은 아니다.
